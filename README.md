# kyc-pdf-trial

> ## ⚠️ NEVER COMMIT CLIENT FILES
> This repository is **public**. Client PDFs, page images, OCR caches, CSV outputs and
> reports contain personal and banking data. Keep them in `data/` and `outputs/` (both
> git-ignored) **on the client laptop only**. Before every push run `git status` and make
> sure no `.pdf`, `.png`, `.csv`, `.json` from real files is staged. Only the synthetic
> PDFs in `tests/fixtures/` (fake data, generated by code) belong in git.

A **starter kit**, not a product. It runs fully on-prem on a CPU-only Windows laptop:
open-source libraries, **no LLMs, no external APIs, no network calls at runtime**.

It answers two trial questions for scanned/digital KYC + loan PDFs:
1. **Classification** - does a PDF contain bank statements, on which pages, and how many months do they cover?
2. **Extraction** - application id, applicant name, co-applicant name and id, and statement
   transactions (date, description, debit, credit, balance) with a running-balance check.

## How it works

```
PDF ─► render.py      text layer present? use it : render page image (pypdfium2, --dpi)
    ─► preprocess.py  grayscale ► deskew ► denoise ► adaptive threshold (OpenCV)
    ─► ocr.py         RapidOCR (ONNX, CPU) ► words + bbox + confidence, cached as JSON
    ─► classify.py    rule score: credit/debit/balance header, date & amount density, column alignment
                      ► bank_statement / application_form / other  (+ optional TF-IDF+LogReg)
    ─► statements.py  group statement pages ► header row ► column boundaries ► rows
                      ► amounts ► prev + credit − debit = balance ? ► months covered
    ─► fields.py      label synonyms + fuzzy match + value right/below + regex validators
    ─► report.py      report.html per PDF, summary.csv, manual_review.csv
```

| Module | What to tune first |
|---|---|
| `kyctrial/config.py` | DPI, threshold, score cut-offs, **field label synonyms + regexes** |
| `kyctrial/classify.py` | keyword lists, weights in `score_page()` |
| `kyctrial/statements.py` | `COLUMN_SYNONYMS` (add the client's bank header names) |
| `kyctrial/parsing.py` | date/amount regexes, OCR digit fixes in `normalise_amount_text()` |

## Windows setup

Needs Python 3.11–3.13 (64-bit) from python.org. In PowerShell:

```powershell
git clone <your-repo-url> kyc-pdf-trial
cd kyc-pdf-trial
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # if blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
python -m pip install --upgrade pip
pip install -r requirements.txt
# optional, for tests / synthetic data:
pip install -r requirements-dev.txt
python -m pytest -q tests
```

Installing needs internet once (pip). After that nothing goes online. If the client laptop is
offline, run `pip download -r requirements.txt -d wheels` on a Windows machine with the same
Python version, copy `wheels\`, then `pip install --no-index --find-links wheels -r requirements.txt`.

## Run

```powershell
mkdir data, outputs        # put client PDFs in data\ (git-ignored)
python -m kyctrial run --input data --output outputs
python -m kyctrial run --input data\file01.pdf --output outputs --max-pages 5 --debug   # quick look
python -m kyctrial run --input data --output outputs --dpi 300 --config local.yaml      # tuning
```

Flags: `--dpi` (render DPI for scanned pages, default 250), `--max-pages N`, `--debug`
(saves each preprocessing step as PNG), `--config` (YAML overrides, see `config.example.yaml`),
`--model` (optional trained page classifier).

Reruns are fast: OCR is cached in `outputs/_ocr_cache/` per page + DPI + preprocessing settings.
Delete that folder after the trial (it contains client text).

## Outputs

| File | What |
|---|---|
| `outputs/summary.csv` | one row per PDF: `has_statements, statement_pages, months_covered, distinct_txn_months, period_start, period_end, n_transactions, reconcile_rate, app_id, name, co_app_name, co_app_id` (+ scores) |
| `outputs/<pdf>/report.html` | open in a browser: fields, statement runs, page thumbnails with label + scores, header (green) / table (blue) / field (orange) boxes, transactions coloured by balance check |
| `outputs/<pdf>/pages.csv` | per page: source (text/image), label, scores, features, OCR confidence, seconds, full text |
| `outputs/<pdf>/transactions.csv` | parsed rows with `reconciles` = ok / fail / na |
| `outputs/manual_review.csv` | ground-truth template - fill the `*_true` columns by hand (never overwritten) |

**How to read it**
- `months_covered` = statement period line if found, else span from first to last transaction month.
  `distinct_txn_months` counts months that actually have transactions - a big difference hints at gaps.
- `reconcile_rate` is the best single quality signal for statements: share of rows where
  previous balance + credit − debit = balance (±₹1). Low rate = OCR digit errors or wrong column mapping.
- A field score is only a ranking hint (fuzzy label match × position), not a probability.

## Measuring accuracy

1. Fill `outputs/manual_review.csv` for the files you checked by hand (even 10 helps).
2. `python -m kyctrial.evaluate --pred outputs/summary.csv --truth outputs/manual_review.csv`

Optional ML page classifier: copy `text` from `pages.csv` files into a `labels.csv` with columns
`text,label`, correct the labels, then `python -m kyctrial train --labels labels.csv --model outputs/page_clf.joblib`
and rerun with `--model outputs/page_clf.joblib` (the ML label is shown next to the rule label).

## Synthetic test data

`python tests/make_fixtures.py` regenerates `tests/fixtures/`: a digital PDF, a harshly degraded
"scanned" PDF (150 dpi, rotated, noisy, black/white) and a scanned PDF without statements. Names are
from Faker; `expected.json` holds the ground truth. Results on this box are in `docs/TRIAL_RESULTS.md`.

## Troubleshooting low-quality scans

| Symptom | Try |
|---|---|
| Few words / low `mean_conf` in `pages.csv` | `--dpi 300`; check `--debug` images: is text broken or blobby? |
| Text too thin / broken after threshold | **decrease** `preprocess.c` (e.g. 8) to keep thin strokes; bigger `block_size` (41–61) for uneven lighting |
| Dark speckle everywhere | keep `denoise: true`; raise `c`; or set `threshold: false` (RapidOCR also works on grayscale - compare) |
| Page tilted in thumbnail | skew > `max_skew_deg` (10) is ignored; rotated 90°/180° pages are **not** handled yet |
| Statement page labelled `other` | lower `classify.statement_min_score`; add the bank's header words to `STATEMENT_HEADERS` / `COLUMN_SYNONYMS` |
| Rows found but `reconcile_rate` low | look at `raw` in `transactions.csv`: digit confusions → extend `normalise_amount_text()`; wrong columns → header names missing from `COLUMN_SYNONYMS` |
| Field empty / wrong | add the exact label text to `config.py` → `fields`; loosen/tighten its `regex` |
| Password-protected PDF | file is listed with an `error` in `summary.csv`; get the password/unlocked copy from the client |
| Slow | `--max-pages`, lower DPI to 200, close other apps; OCR is ~1–3 s/page on CPU |
